Reference

Python API

Every public type and function, ordered the way a run passes through them.

Common names are re-exported from the package root, so from metering import run_hidden_fault works and the module paths below tell you where each one lives. Every decoder in this API is strict, which means an unknown field, an incorrect JSON type, or a Boolean standing in for an integer is rejected rather than repaired.

Schema

metering.schema holds the artifact vocabulary and the strict decoding rules that every other module reuses. Nothing here reads or writes files, so it is the one module with no dependencies inside the package.

StrictFields(error=SchemaError)

Strict JSON field checks bound to one error type. Methods are mapping, exact_keys, text, integer, boolean, sha256_digest, uuid4, and finite_json. The error type is chosen by the caller because the same rules are enforced at several boundaries, so a malformed action raises EventError and a malformed manifest raises ReportError while both use these checks.

SchemaError

Base class for every strict-decoding failure, derived from ValueError. EventError, HiddenFaultError, TraceError, BindingError, and ReportError all derive from it, so a caller can catch one boundary precisely or catch them all at once.

Constants

Schema versions for events, public instances, references, manifests, reports, and calibration summaries. Event types are run_started, interaction, protocol_error, and termination. Termination reasons are normal_finish, invalid_action, harness_crash, and budget_exhausted. Changing a schema version is a compatibility decision, because each one gates a strict decoder that replay depends on.

Actions, observations, and events

metering.events defines the complete protocol vocabulary and its canonical JSON conversion. The module carries data only and never interprets a run.

Diagnose(test_id: str)

Request one test from the public diagnostic catalogue.

Repair(fault_id: str)

Select a public fault identifier as the proposed repair. A later repair replaces an earlier one and makes any verification before it stale.

Verify()

Verify the current repair. Valid only after a repair has been selected, and the delivered result is a content-free acknowledgement.

Finish()

Ask the controller to terminate the run normally. This is the only action that produces a successful termination.

DiagnosticObservation(test_id: str, positive: bool)

The deterministic Boolean outcome of one public diagnostic test. This is the only observation that carries diagnostic content, and it is the only one the information meter reads.

RepairObservation(fault_id: str)

Acknowledges which repair was applied, without saying whether it matches the hidden fault.

VerificationObservation()

Acknowledges that verification happened and carries no result. Returning the outcome here would turn verification into a second diagnostic oracle that no meter counts.

FinishObservation()

Acknowledges a valid finish action.

RawActionCost(...)

RawActionCost(
    diagnostic_observations: int = 0,
    repair_actions: int = 0,
    verification_actions: int = 0,
    total_actions: int = 0,
)

Uncombined resource counts from one action. Instances add together with +, and zero(), to_dict(), and strict from_dict() are provided. The counts stay in separate columns at every layer, because only the reader knows how to trade a diagnostic against a repair.

Event(...)

Event(run_id, world_id, world_version, instance_id, instance_version,
      step, event_type, payload, resources=RawActionCost(), schema_version=1)

One canonical, interpretation-free fact in an append-only trace. The payload is deep-copied and checked for finite JSON on construction, so an event cannot be mutated after it is recorded.

action_from_dict(data) → Action

Decode one canonical action object, rejecting unknown or extra fields. action_to_dict(action) is the inverse and accepts only typed actions, since a plain mapping arriving from a harness must surface as a protocol failure.

observation_from_dict(data) → Observation

Decode one canonical observation object. observation_to_dict(observation) is the inverse.

Hidden-fault world

metering.hidden_fault defines the fixed public catalogue, the truth-free instance a policy may receive, and the mutable world that owns the selected fault.

DiagnosticTest(test_id, description, positive_fault_ids)

A public deterministic yes/no test. positive_fault_ids is the published observation model, which is what lets a policy and an offline meter compute the same candidate set. outcome(fault_id) returns the result for a declared fault. A test that is positive in every state is rejected, because it would cost one action and remove zero bits.

PublicInstance(...)

Everything a cooperative policy is allowed to receive: world and instance identity, the ordered fault identifiers, and the diagnostic catalogue. It contains no selected fault, and calibration checks that it is byte-identical across all eight states.

HiddenFaultSpec(...)

A versioned world definition. HiddenFaultSpec.default() returns the canonical eight-fault specification, whose catalogue holds three balanced split tests followed by one singleton test per fault. public_instance(instance_id) materializes the public description.

HiddenFaultWorld(spec, hidden_fault_id, *, instance_id=...)

Owns the selected fault and the mutable repair state. public_description() returns the truth-free instance, validate_action() decides legality without changing state, and apply() performs one validated action and returns its observation and raw cost. The controller-only methods generated_instance_reference() and final_reference_state() supply private material for the commitment and the offline verifier.

ActionValidation(valid, code, message)

Structured validation result built with accept() or reject(code, message). Validation is separate from application because a rejected action still costs one unit of budget and must be recorded.

Policies

metering.policies defines the cooperative harness contract and three deterministic reference policies.

HarnessPolicy

next_action(instance: PublicInstance,
            observations: Sequence[Observation]) → Action

descriptor() → dict[str, Any]

A policy returns exactly one typed action per call, plus a descriptor holding its name, version, configuration, and a seed policy of either {"kind": "none"} or {"kind": "fixed", "seed": int}. The descriptor is validated before the run starts, because an undeclared configuration would make the result impossible to reproduce.

remaining_candidates(instance, observations) → tuple[str, ...]

Filter the fault list using delivered diagnostic outcomes and the published observation model. Repair and verification results are ignored, since neither is diagnostic evidence. A history that no state can explain raises PolicyError.

BalancedSearchPolicy()

Chooses the unused catalogue test whose split of the remaining candidates is most even, breaking ties by catalogue order. It identifies every fault in three observations, for 24 across the suite.

SequentialSearchPolicy()

Checks singleton candidates in public order and infers the eighth state after seven negative results rather than testing it redundantly. Its per-state costs are [1, 2, 3, 4, 5, 6, 7, 7], for 35 across the suite.

SeededRandomSearchPolicy(seed: int = 20260722)

Ranks informative unused tests by a SHA-256 hash of the seed, the diagnostic history, and the test identifier. Hashing rather than random.Random keeps replay stable across Python releases, which is what makes this policy useful as a determinism check.

Runner

metering.runner owns the action loop and writes the four artifacts of a run in a fixed order.

run_hidden_fault(...)

run_hidden_fault(
    policy: HarnessPolicy,
    hidden_fault_id: str,
    run_dir: str | Path,
    *,
    spec: HiddenFaultSpec | None = None,
    instance_id: str = "hidden-fault-public-v1",
    run_id: str | None = None,
    action_budget: int = 16,
    sync_trace: bool = False,
) → RunResult

Create one hidden-fault world and run a cooperative policy against it. The run directory must be new or empty. Passing sync_trace=True flushes each event to disk, which costs time and is worth it when studying crashes.

run_experiment(...)

run_experiment(world, policy, run_dir, *, run_id=None,
               action_budget=16, sync_trace=False) → RunResult

Run an existing HiddenFaultWorld and write the artifacts. Use this when the world needs to be constructed separately, for example with a non-default specification.

RunResult

Holds paths, the decoded manifest, the tuple of events, the private reference, and the derived report. The succeeded property reports exact overall completion, and run_dir is a shortcut to the directory.

Controller(world, policy, trace, *, run_id, artifact_set_id, action_budget=16)

The action loop itself. run() requests actions until the policy finishes, breaks the protocol, crashes, or exhausts the budget, and returns a ControllerOutcome. Use run_experiment unless you are writing artifacts yourself.

Traces and canonical encoding

metering.trace provides the one valid byte representation of every artifact, plus strict reading and append-only writing.

canonical_json(value) → str

Encode finite JSON deterministically with sorted keys and compact separators. canonical_document_bytes(value) adds the trailing newline that a document artifact carries, and canonical_events_bytes(events) does the same per line for a trace.

strict_json_loads(text, *, context="JSON") → Any

Decode JSON while rejecting duplicate object keys and non-finite numbers. Both are rejected rather than resolved, because either one would let two readers disagree about what a file says.

write_json_atomic(path, value, *, private=False) → Path

Write one canonical document through a temporary file and an atomic rename, so a reader never sees a partial artifact. Private output is created with restrictive permissions.

RunPaths(run_dir)

The four artifact paths of one run directory, as manifest, events, reference, and report. Build one with RunPaths.at(path).

TraceWriter(path, *, sync=False)

Create a new trace with exclusive creation and append canonical events with append(event). Each append checks the next monotonic step and the stable run identity, so a trace cannot silently skip a step or mix two runs.

TraceReader(path)

Decode a trace while validating schemas, identity, and contiguous step order. load(require_nonempty=True) returns the events as a tuple, and read_events(path) is the shorthand.

interaction_signature(events) → tuple[str, ...]

A signature of what happened, with controller-generated identifiers masked. Two runs of the same seeded policy get different run identifiers by design, so this is what a determinism check compares.

Binding

metering.binding commits to the private truth before the policy runs.

compute_reference_commitment(artifact_set_id, binding_nonce, generated_instance) → str

Hash the artifact identity, a fresh random nonce, and the complete generated-instance identity into one digest. The nonce is what makes this useful, because a bare hash of one of eight faults could be reversed by hashing all eight. With the nonce held back until the reference is revealed, the manifest commits to the truth without disclosing it.

reference_commitment_payload(...) → dict

The exact JSON value that gets hashed. It requires the complete identity, so adding or omitting a truth-bearing field cannot quietly change what the commitment covers.

Replay

metering.replay rebuilds a finished run from its files without executing any policy or world code.

replay_trace(...)

replay_trace(manifest, events, reference, *, artifact_bytes=None)
    → ReplayState

Validate the manifest and reference schemas, the artifact identity, the private commitment, every event envelope, every transition and its recorded cost, the termination reason, and the private final state, then compare the exact artifact bytes and their bound hashes. Pass artifact_bytes when the bytes on disk are available, since that is what binds the result to files a reader can inspect.

ReplayState

The reconstructed controller state: the public instance, the revealed hidden fault, the artifact identity and hashes, the budget, the replayed interactions, the termination reason and step, the final repair and its step, the verification steps, and whether a finish or a protocol error occurred.

ReplayedInteraction(event_step, action, observation)

One action and its observation, recovered from the trace as typed values.

Reports

metering.report turns a replayed state into three separate readings. Nothing here can affect a run, because it reads artifacts that are already written and hashed.

build_report(...)

build_report(manifest, events, reference, *, artifact_bytes=None)
    → dict[str, Any]

Replay the artifacts, then return correctness, raw resources, diagnostic information, the declared scope, and the hashes of the three inputs. The scope block names what every reading is conditional on, which keeps a number from being quoted later as though it described agents in general.

regenerate_report(run_dir) → dict[str, Any]

Read the three raw artifacts from disk and atomically replace report.json, but only after strict replay succeeds. A run whose artifacts disagree keeps whatever report it already had.

aggregate_reports(reports) → dict[str, Any]

Sum the raw units across runs and divide total bits by total observations. Averaging the per-run ratios instead would give a one-observation run the same weight as a seven-observation run, which would report a suite as more efficient than the observations it paid for.

Calibration

metering.calibration runs the whole instrument against answers that are already known.

run_calibration(...)

run_calibration(
    output_dir: str | Path = "runs/calibration",
    *, seed: int = 20260722,
    action_budget: int = 16,
    force: bool = False,
) → CalibrationResult

Run every hidden state against every reference policy, rebuild each report from disk, check the expected readings, confirm seeded replay determinism, exercise all four termination paths, and confirm that a corrupted trace is rejected. Every check is recorded in calibration.json whether it passed or not. The budget must be at least 10, since a reference policy may need seven diagnostics plus a repair, a verification, and a finish.

CalibrationResult(output_dir, summary)

The output path and the aggregate summary, including per-state diagnostic counts, total bits, and efficiency for each reference policy.

CalibrationFailure(message, summary=None)

Raised after one or more declared checks fail. The summary is attached to the exception and has already been written to disk.
