This is an instrument calibration, not a leaderboard. Results describe the declared eight-fault world, policy, budget, and configuration. They are not an overall agent score or a universal measure of harness quality.

01 · What it measures

Three answers that stay separate

Low cost cannot cancel a wrong result. Metering first checks exact completion, then reports costs and delivered diagnostic information in their own units.

  1. 1

    Exact correctness

    A successful run must satisfy every condition below.

    • The final repair matches the hidden fault.
    • Verification happened after the final repair.
    • The policy ended with a valid finish action.
    • The action budget was respected.
  2. 2

    Raw resource counts

    The report keeps diagnostic observations, repairs, verifications, total actions, and budget exhaustion separate. It never blends them into invented points.

    3 diagnose 1 repair 1 verify 6 total
  3. 3

    Information exposure

    The meter counts how much uncertainty the delivered catalogue results remove. With eight equally likely candidates, three even yes-or-no splits can narrow the set to one.

    8 candidates 4 candidates 2 candidates 1 candidate

What “information” means here

It is the realized reduction in uncertainty caused by diagnostic results the policy actually received. Choosing a test is not evidence. Repairing, verifying, and finishing do not reduce the diagnostic candidate set. This meter does not know whether a model understood or internally used an observation.

04 · Install and run

From checkout to calibrated artifacts

Metering requires Python 3.11 or newer. The runtime package has no third-party dependencies. Development commands use uv.

Option A

Run directly from a checkout

git clone https://github.com/muchmirul/metering.git
cd metering
uv run python -m metering calibrate \
  --output runs/calibration

uv run creates or uses the project environment and runs the package from the checkout.

Option B

Install this checkout

python -m pip install .
metering calibrate --output runs/calibration

The module form, python -m metering, and the installed metering command provide the same subcommands.

terminal
$ uv run python -m metering calibrate --output runs/calibration
calibration passed: runs/calibration
balanced diagnostics: 24; sequential diagnostics: 35

Output safety

The output directory must be new or empty. --force replaces only a directory carrying Metering’s own calibration marker; it refuses an arbitrary non-empty directory.

Useful options

--seed declares the seeded baseline’s integer seed. --budget sets the reference-run action budget and must be at least 10 for calibration.

Run the test suite

uv run --extra test pytest -q

The tests do not need network access or a model server.

One run from Python

Choose the controller’s hidden state and a policy.

The hidden_fault_id argument configures the controller-owned world. It is not included in the public value passed to next_action. The run directory must be new or empty.

from metering import BalancedSearchPolicy, run_hidden_fault

result = run_hidden_fault(
    BalancedSearchPolicy(),
    hidden_fault_id="fault-5",
    run_dir="runs/example",
    run_id="example",
    action_budget=16,
)

print(result.succeeded)
print(result.report["resources"])
print(result.report["diagnostic_information"])

05 · Artifacts and replay

The saved run is the experiment record

A seed is not enough. Metering saves the materialized public instance, the raw interaction, private reference state, policy descriptor, implementation provenance, and the derived report.

▾ runs/example/
manifest.jsondeclared setup + opaque commitment
events.jsonlappend-only actions and observations
reference.jsonprivate truth + nonce + input bindings
report.jsonoffline verifier and meter output
Declared

manifest.json

Contains the public instance, world specification, budget, exact policy descriptor, implementation versions, execution boundary, fresh artifact-set identifier, and salted commitment to private generated truth.

Raw

events.jsonl

Canonical JSON Lines with strict schemas and contiguous steps. It records the start, each typed interaction or protocol error, raw resource units, and termination.

Keep private

reference.json

Contains the selected hidden fault, private commitment nonce, final controller state, and exact manifest and event hashes. It is never passed to the policy.

Derived

report.json

Contains separate correctness facts, resource counts, information progression, scope limits, and byte-exact hashes of all three raw inputs. It does not expose the nonce.

Offline regeneration

Delete or distrust the report? Rebuild it from the three bound raw inputs.

python -m metering report runs/example
  1. 1
    Read strictly

    Decode the manifest, event stream, and private reference. Duplicate keys, unexpected fields, non-finite numbers, and wrong JSON types are rejected.

  2. 2
    Bind and replay

    Check identifiers, byte hashes, private commitment, implementation provenance, transitions, observations, and costs without calling the policy or world.

  3. 3
    Replace atomically

    Only a valid reconstruction replaces report.json. A failed replay does not overwrite an existing good report.

Calibration adds a suite summary. The chosen output root contains calibration.json, reference runs for all policies and states, seeded replay runs, and controller checks. Every individual run still has the same four-file shape.

06 · Integrity and privacy boundary

Detect mixing and corruption without pretending it is authentication

The mechanism is deliberately narrow. It provides API non-disclosure and internally consistent artifacts for a cooperative, in-process experiment.

◉

Policy receives

  • Immutable public instance
  • Eight public fault identifiers
  • Fixed diagnostic catalogue
  • Delivered observation history
  • Content-free verification acknowledgement
callback boundary
◆

Controller keeps private

  • Selected hidden fault
  • Commitment nonce
  • Verification pass or fail during execution
  • Final reference state
  • reference.json contents
ID

Fresh artifact identity

A caller-controlled run_id is only a label. Every execution receives a controller-generated artifact_set_id, so swapping one raw file between runs is detected even if labels match.

#

Salted private commitment

Before the first callback, the controller commits to the generated-instance identity with SHA-256 and a fresh private nonce. The public manifest carries only the opaque digest.

↻

Exact byte bindings

The private reference binds the manifest and events; the report records hashes of all three raw inputs. Replay also checks semantic consistency rather than trusting hashes alone.

Hashes and commitments are not signatures.

They detect corruption, stale files, and accidental mixing. They do not authenticate an artifact set against an attacker who can coherently rewrite every file. The in-process callback boundary is not a hostile-code sandbox.

07 · Implement a policy

Return one typed action at a time

A policy needs two methods. descriptor() declares exact provenance. next_action(instance, observations) receives only public state and returns Diagnose, Repair, Verify, or Finish.

first_useful_policy.pyPython
from metering import (
    Diagnose,
    DiagnosticObservation,
    Finish,
    Repair,
    RepairObservation,
    VerificationObservation,
    Verify,
    remaining_candidates,
    run_hidden_fault,
)

class FirstUsefulPolicy:
    name = "first-useful"
    version = "1"

    def descriptor(self):
        return {
            "name": self.name,
            "version": self.version,
            "configuration": {
                "choice": "public_catalogue_order"
            },
            "seed_policy": {"kind": "none"},
        }

    def next_action(self, instance, observations):
        if observations and isinstance(
            observations[-1], VerificationObservation
        ):
            return Finish()
        if observations and isinstance(
            observations[-1], RepairObservation
        ):
            return Verify()

        candidates = remaining_candidates(
            instance, observations
        )
        if len(candidates) == 1:
            return Repair(candidates[0])

        used = {
            item.test_id for item in observations
            if isinstance(item, DiagnosticObservation)
        }
        candidate_set = set(candidates)
        for test in instance.diagnostic_tests:
            positive = candidate_set.intersection(
                test.positive_fault_ids
            )
            if (test.test_id not in used
                    and 0 < len(positive) < len(candidates)):
                return Diagnose(test.test_id)

        raise RuntimeError("no informative test remains")

result = run_hidden_fault(
    FirstUsefulPolicy(),
    "fault-5",
    "runs/first-useful",
    action_budget=16,
)
print(result.succeeded)
01

Use the exact descriptor shape

The only top-level keys are name, version, configuration, and seed_policy. Values must be finite JSON data. A random policy declares {"kind": "fixed", "seed": 123}.

02

Read only delivered evidence

remaining_candidates filters the public candidates using diagnostic observations. It ignores repair and verification acknowledgements, as the information meter does.

03

Return typed actions

A plain dictionary is not repaired into an action. Unknown tests, unknown faults, verifying before repair, and malformed return values end as explicit protocol failures.

04

Repair, verify, then finish

Verification is valid only after a repair. A later repair makes earlier verification stale. The acknowledgement does not reveal whether the repair matched.

Budget behavior is observable.

Every returned action attempt, including an invalid attempt and Finish, uses one action unit. The controller makes no extra callback after the budget is exhausted. An ordinary exception from next_action is recorded as a harness crash.

08 · Read the boundary literally

What Metering does not establish

A controlled measurement is useful because its limits are explicit.

01

Not model understanding

The information meter sees delivered diagnostic results. It cannot observe private reasoning or prove that a model understood or used them.

02

Not universal quality

The calibrated costs belong to one deterministic eight-state world with a uniform prior and fixed catalogue. They do not measure real software work.

03

Not a security sandbox

Policies run cooperatively in process. Metering cannot stop a callback that never returns or recover from hard exits, segmentation faults, out-of-memory termination, or interpreter failure.

04

Not authentication

SHA-256 bindings are integrity checks, not signatures. A party able to rewrite a complete artifact set can construct a different internally consistent set.

05

Not a combined score

Correctness, diagnostics, repairs, verifications, and total actions remain separate. The package does not turn them into a leaderboard number.

06

Not a production failure lab

There is no external harness protocol, process isolation, model provider, injected timeout, dropped-response simulation, database, or dashboard in the implemented scope.

Versions and release notes

Use published releases as the version source

This guide does not hard-code a “latest” release number. GitHub Releases is the place to find published versions, change notes, and source archives. A checkout of the main branch may contain changes made after a release.

The release/package version is recorded as provenance, but it does not by itself block replay. Accepted schemas and compatible controller, verifier, and meter versions are the replay gates.
